Result: 2026-11-09: the repository exists with an initial commit, the deploy key was added, and the mirror runs on 2026-11-09 pushed `main` and the `v0.1.0` and `v0.1.1` tags.
- [x] npm organisation: the npm org `zandovi` exists (it owns the `@zandovi` scope), and the maintainer's npm account has 2FA enabled, which approving a staged version requires. Result: 2026-11-09: the `zandovi` org owns the scope (maintainer `deq6`), and the staged 0.1.1 was approved with 2FA.
- [x] npm auth for the first publish: create a granular access token with "Read and write (stage only)" and no 2FA bypass, covering `@zandovi/n8n-nodes-zandovi` (All packages, or the `@zandovi` scope if offered, since the package does not exist yet), and add it as the `NPM_TOKEN` secret of the public repository `zandovi/n8n-nodes-zandovi` before the first mirror run. Its `publish.yml` passes it to `npm stage publish --provenance`, which can create a new package. Do not enable the package setting "Require two-factor authentication and disallow tokens" until it is confirmed not to block staging with a token. Result: 2026-11-09: a stage-only token without 2FA bypass is the `NPM_TOKEN` secret of the public repository; it staged 0.1.1.
- [x] First mirror run, once the deploy key and `NPM_TOKEN` secrets exist: start it manually (Actions → "Publish n8n-node/ to n8n-nodes-zandovi" → Run workflow, on `main`); no extra commit is needed. The public repository gets the commit and a `v<version>` tag, and its publish workflow stages the version with the token. If staging fails, re-run it on the same tag. A re-run with no change neither commits nor retags. npm may publish a public `0.0.0-stage` placeholder for a package staged before it exists; record whether it appeared. Result: 2026-11-09: `v0.1.0` was tagged on a commit whose `publish.yml` still ran a direct `npm publish`, and its run failed with `ENEEDAUTH` before `NPM_TOKEN` existed. Tags are never moved, so the first release is 0.1.1: `v0.1.1` staged successfully. The public `0.0.0-stage` placeholder appeared (2 files); deprecate it with `npm deprecate @zandovi/n8n-nodes-zandovi@0.0.0-stage "Placeholder created by npm staged publishing; install 0.1.1 or later"`.
- [x] Approve the staged version with 2FA: npmjs.com → `@zandovi/n8n-nodes-zandovi` → Staged Packages → Approve (or `npm stage list`, then `npm stage approve <stage-id>`). The version is not installable before this. A staged version that should not go out is rejected instead, and the same tag re-run; a version already approved is fixed by bumping the patch version. Result: 2026-11-09: 0.1.1 approved and published at 15:12 UTC; `latest` is 0.1.1.
